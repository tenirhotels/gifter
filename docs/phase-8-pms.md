# Фаза 8: бронь по PMS (Hotel Hub / Exely)

Gifter подтверждает номер брони по PMS. Источник — **на выбор** (страница «Подключение к PMS»), ответ у обоих в формате Exely `{"booking": {...}}` и разбирается одним кодом. Gifter только читает; брони в PMS не создаёт.

| | Hotel Hub (свой сервис) | Exely напрямую |
|---|---|---|
| Запрос | `GET {адрес хаба}/v1/properties/{код}/bookings/{номер}` | `GET https://connect.hopenapi.com/api/read-reservation/v1/properties/{propertyId}/bookings/{номер}` |
| Вход | токен хаба с правом `bookings` | OAuth: `client_id` + `client_secret` → `POST /auth/token` (client_credentials), токен 15 минут, Gifter кеширует и обновляет сам |
| Что в настройках | адрес, код отеля, токен | идентификатор отеля, client_id, client_secret (адрес — по умолчанию connect.hopenapi.com) |
| Статус комнат | `roomStays[].hub.status`, возраст данных `hub.stale` | нет (статус брони Active/Cancelled) |
| 503 «данные устарели» | да | нет |
| Где взять доступ | хаб: «API и токены» | Exely: «Настройка гостиницы → Подключение API»; доступ к Read Reservation API включается отдельно |

Описание API хаба — `docs/bookings-api.md` в репозитории Hotel Hub (право токена `bookings`).

## Решения владельца

| Вопрос | Решение |
|---|---|
| Объём | Проверка брони при внесении. Фоновая сверка, заезд и погашение по статусам PMS — следующие шаги |
| Нет брони / хаб недоступен | **Всегда строго:** без подтверждения PMS бронь не сохраняется |
| Подключение | Страница в панели «Администрирование → Подключение к PMS»; токен хранится зашифрованным и не показывается |

## Подключение

1. Выбрать источник и получить доступ: хаб — токен с правом `bookings`; Exely — ключи подключения (client_id, client_secret).
2. В Gifter (администратор): Администрирование → «Подключение к PMS» → источник, поля выбранного источника, «Проверять брони по PMS» → «Сохранить» → «Проверить связь» (запрашивается несуществующая бронь; «не найдена» — связь и ключи в порядке).
3. Пустое поле токена или client_secret при сохранении оставляет прежнее значение. Секреты хранятся зашифрованными и не показываются; смена настроек пишется в журнал аудита (секреты — только факт смены).
4. Переключение между источниками — сменой выбора и сохранением; сохранённые брони не меняются.

Пока подключение выключено, бронь вносится вручную, как в фазе 6.

## Как вносится бронь

Front Office вводит **только номер брони**. Gifter запрашивает PMS и показывает гостя, даты, число комнат и совпадение имени; после «Сохранить бронь» гость и даты берутся из PMS (введённое руками не используется).

- **Гость:** из гостей действующих комнат и заказчика брони берётся тот, кто совпал с получателем сертификата, затем с заказчиком сертификата; иначе — несовпадение (нужна причина, бронь уходит на проверку Финансов, как в фазе 6).
- **Даты:** заезд — самый ранний, выезд — самый поздний по действующим комнатам; отменённые комнаты не учитываются. Даты должны попадать в срок сертификата.
- **Бронь отменена в PMS** (все комнаты) — привязать нельзя.
- **Данные хаба устарели** (`hub.stale: true`) — бронь найдена, сохраняется с пометкой «данные устарели N мин» в истории и в карточке.
- Бронь по исключению для истёкшего сертификата проверяется так же.
- В карточке сертификата у номера брони: «Подтверждена по PMS (дата, возраст данных)» или «Внесена вручную».

## Сверка брони с сертификатом (19.10.2026)

При вводе номера форма показывает результат сверки (✓ / ✗) по пунктам. Есть расхождения — причина обязательна, бронь уходит на согласование Финансам с перечнем расхождений и причиной (они записываются в причину брони и в историю).

| Пункт | Правило |
|---|---|
| **Заезд** | в сроке действия сертификата — иначе бронь не принимается (причина не поможет: срок меняет менеджер, или бронь по исключению) |
| **Ночи** | число ночей в брони (выезд − заезд) не больше ночей в составе сертификата: услуги «ночь» пакета плюс доп. ночи. Сертификат на 1 ночь — заезд и выезд на следующий день; 1 ночь + доп. ночь — не больше 2 ночей. Больше — расхождение; меньше — нет. Если в составе нет услуги «ночь», ночи не сверяются |
| **Тариф** | все действующие комнаты брони — по тарифу «Сертификат»: название задаётся в настройках PMS («Тариф для сертификатов», сверка по части названия или коду, без учёта регистра); другой тариф, как и отсутствие тарифа в брони, — расхождение. Пустое поле — тариф не сверяется |
| **Имя гостя** | совпадает с получателем или заказчиком сертификата; иначе расхождение |

**Имя при несовпадении.** Если имя гостя не совпало ни с получателем, ни с заказчиком, показывается и хранится только имя и первая буква фамилии («Bekki R.»): полные данные чужого гостя в Gifter не попадают — в форме, карточке, очереди Финансов, истории и аудите.

## Ошибки (бронь не сохраняется)

| Ответ PMS | Сообщение сотруднику |
|---|---|
| 404 `not_found` | Бронь не найдена в PMS — проверьте номер. Хаб держит окно броней: очень старая или далёкая бронь может быть в Exely, но не у хаба |
| 503 `source_unavailable` | Данные PMS устарели (нет связи с Exely) — попробуйте позже; «не найдена» не говорим |
| сеть, таймаут, 5xx | PMS недоступна — попробуйте позже |
| 401 / 403 | Хаб: токен отклонён (нет права `bookings`). Exely: ключи отклонены или нет доступа к Read Reservation API — к администратору |
| 400 | Номер брони PMS не принимает |
| 429 | Лимит (хаб: 120 запросов в минуту на токен; Exely: запрос токена 15 в минуту на IP) — подождать минуту. Подсказка в форме кешируется на 30 секунд, токен Exely — на 14 минут |
