# Фаза 2 — пользователи, роли и деньги

У пользователя может быть несколько ролей, права складываются. Без роли или при отключённом пользователе вход в панель закрыт. Удаления пользователей нет — только отключение. Последнего активного администратора нельзя отключить или лишить роли.

Матрица прав — одно место в коде: `app/Enums/Permission.php`. Проверки идут через политики моделей (видимость разделов и записей) и `authorize()` у каждого действия панели — скрытое действие нельзя вызвать и в обход интерфейса. Удаление запрещено политиками для всех, включая администратора.

## Правила денег

- Выпуск продажи — только когда поступления покрывают стоимость. Сверка Финансами выпуск не задерживает: Kaspi-оплату продавец отмечает сам, Финансы сверяют позже.
- Перечисление на р/с продавец отметить не может — только Финансы по выписке.
- Оплаченный счёт не отменяется. Сверенная оплата повторно не сверяется.
- Аннулировать напрямую можно только сертификат без поступлений. С оплатой — только через возврат.
- Сумма возврата — от 0 до суммы поступлений. Возврат 0 ₸ (аннулирование без выплаты) после согласования сразу считается завершённым.

## Как трактованы места ТЗ, которые можно понять по-разному

1. **Продавец и состав.** Продавец собирает свой черновик сам (пакет и/или услуги). До выставления счёта это не продажа, поэтому правка состава черновика доступна продавцу.
2. **Директор по продажам** видит все сертификаты только на чтение — чтобы оценивать продажи пакетов.
3. **Front Office** отмечает бронь, заезд и погашение вручную; привязка брони PMS — фаза 9.
4. Справочники поставщиков и категорий для директора — фаза 3. Учёт фактической себестоимости услуг (билеты, питание) для маркетинговых сертификатов — вместе с поставщиками в фазах 3 и 5; сейчас расход считается по прайсу.
5. Общий процесс исключений с согласованием Финансов — фаза 7; возврат уже работает по той же схеме «запрос → решение Финансов».

## Пользователи

- Первый: `php artisan gifter:create-user` — спросит имя, email, пароль и роли (первому по умолчанию предлагается «Администратор»).
- Дальше — раздел «Администрирование → Пользователи».
- При обновлении с фазы 1 миграция выдаёт существующим пользователям роль администратора, чтобы никто не остался без входа.
