# Фаза 2 — пользователи и роли

У пользователя может быть несколько ролей, права складываются. Без роли или при отключённом пользователе вход в панель закрыт. Удаления пользователей нет — только отключение. Последнего активного администратора нельзя отключить или лишить роли.

Матрица прав — одно место в коде: `app/Enums/Permission.php`. Проверки идут через политики моделей (видимость разделов) и `authorize()` у каждого действия панели (скрытое действие нельзя вызвать и в обход интерфейса). Удаление запрещено политиками для всех, включая администратора.

## Как трактованы места ТЗ, которые можно понять по-разному

1. **«Продажи» и состав.** Продавец собирает черновик сам (пакет и/или отдельные услуги) — без этого он не может продать. До выставления счёта это не продажа, поэтому правка состава черновика доступна и продавцу.
2. **Корректировки менеджера** — сейчас это срок действия и аннулирование выпущенного сертификата. Изменение состава *после выпуска* в ядре пока запрещено: оно требует правил пересчёта и доплаты/возврата.
3. **«Просмотр разрешённых сертификатов»** продавцом — сейчас все сертификаты (небольшая команда, проще искать дубли). Ограничение «только свои» включается одной строкой в политике.
4. **Директор по продажам** видит сертификаты только на чтение — чтобы оценивать продажи пакетов.
5. **Финансы** пока только просматривают. Согласование исключений — фаза 7.
6. **Front Office** отмечает бронь, заезд и погашение вручную; привязка брони PMS — фаза 9. Справочники поставщиков и категорий для директора — фаза 3.

## Пользователи

- Первый: `php artisan gifter:create-user` — спросит имя, email, пароль и роли (первому по умолчанию предлагается «Администратор»).
- Дальше — раздел «Администрирование → Пользователи».
- При обновлении с фазы 1 миграция выдаёт существующим пользователям роль администратора, чтобы никто не остался без входа.
