# Фаза 4 — продажа сертификата

## Процесс

```
Продукт (пакет)  →  Покупатель и получатель  →  Доп. услуги и итог  →  Счёт
        ↓ одна транзакция: черновик + снимок цен + счёт
Оплата отмечена (Kaspi/Halyk — продавец, р/с — Финансы)  →  «Выпустить»  →  PDF с QR
```

### Мастер продажи (Сертификаты → «Новый сертификат»)

1. **Продукт** — пакет и **количество сертификатов** (по умолчанию 1); срок действия виден сразу. Менеджер может выбрать дату продажи, а для бесплатного пакета — цель, основание и срок (по пакету / длительность с даты / до конкретного дня).
2. **Покупатель и получатель** — поиск по фамилии, компании, БИН или создание нового (+). Получатель необязателен.
3. **Состав и стоимость** — доп. услуги к пакету и расчёт по прайсу на дату продажи: каждая строка, итог, предупреждение, если у услуги нет цены.
4. **Счёт** — сразу выставить счёт на всю сумму (Kaspi / Halyk / р/с) с номером счёта банка. Для бесплатного шага нет.

Всё сохраняется одной транзакцией: если что-то не прошло (например, нет цены), ничего не создаётся. Дальше — страница сертификата: отметить оплату → «Выпустить».

### Несколько сертификатов — покупка (с 25.10.2026)

Количество больше 1 — оформляется **покупка №N**: одинаковые сертификаты (пакет, доп. услуги, срок, покупатель), у каждого свой номер и получатель. После мастера открывается страница покупки.

- **Платная:** один счёт на всю покупку (внутри — по строке на сертификат с общим номером счёта) → «Оплачен» на странице покупки отмечает весь счёт (р/с — только Финансы) → «Выпустить» (только когда оплачен каждый сертификат) → «PDF всех».
- **Бесплатная:** цель, основание, срок → директор «Согласовать» → «Выпустить» → «PDF всех».
- До выпуска счёт, оплата, состав, выпуск и аннулирование — только всей покупкой (на странице сертификата их нет, есть кнопка «Покупка №N: счёт, оплата, выпуск»). Получатель — в каждом сертификате отдельно.
- После выпуска сертификаты живут отдельно: бронь, погашение, возврат — поштучно; возврат одного не затрагивает остальные.
- Финансы: в реестре оплат у строки — «Покупка №N (из N)»; «Сверено» по любой строке сверяет весь счёт покупки.
- Отдельного пункта меню у покупок нет: они открываются со страницы сертификата, из колонки «Покупка» реестра (фильтр «Из покупки №») и с главной («Бесплатные покупки ждут согласования» — директору, «Покупки к выпуску» — продажам). Продавец видит только свои покупки.

### Снимок цен

Цена, себестоимость, поставщик и признаки исполнения каждой услуги фиксируются в строке сертификата на дату продажи (фазы 1, 3). Изменения прайса и пакетов на выданные сертификаты не влияют. Стоимость сертификата = сумма услуг пакета и доп. услуг по прайсу (решение 22.10.2026).

## Документ сертификата (PDF)

Кнопка **PDF** на странице выпущенного сертификата (статусы «Активен», «Забронирован», «Используется»). В документе:

- название и контакты отеля (`GIFTER_HOTEL_NAME`, `GIFTER_HOTEL_CONTACTS` в `.env`);
- номер, получатель (если не указан — «Предъявитель сертификата»), пакет, срок действия;
- состав: услуги и количество, **без цен**;
- условия (`config/gifter.php` → `certificate.terms`): погашение целиком, без обмена на деньги и т. д.;
- QR-код на страницу проверки.

Каждое скачивание пишется в историю сертификата («Скачан PDF сертификата»).

## Проверка по QR

QR ведёт на `/v/<код>` — публичную страницу без входа. Код — случайные 32 символа, создаётся при выпуске; номер сертификата для проверки не используется (его легко угадать).

Страница показывает **только** номер, статус («Действителен», «Используется», «Использован», «Срок действия истёк», «Аннулирован»), дату окончания и пакет. Имён, контактов и сумм нет. Ограничение — 30 проверок в минуту с одного адреса; страница закрыта от поисковиков.

Для рабочего сервера в `.env` должен быть указан настоящий `APP_URL` — из него строится ссылка в QR.
