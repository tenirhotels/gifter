# Фаза 4 — продажа сертификата

## Процесс

```
Продукт (пакет)  →  Заказчик и получатель  →  Доп. услуги и итог  →  Счёт
        ↓ одна транзакция: черновик + снимок цен + счёт
Оплата отмечена (Kaspi/Halyk — продавец, р/с и наличные — Финансы)  →  «Выпустить»  →  PDF с QR
```

### Мастер продажи (Сертификаты → «Новый сертификат»)

1. **Продукт** — пакет и **количество сертификатов** (по умолчанию 1); срок действия виден сразу. Менеджер может выбрать дату продажи, а для бесплатного пакета — цель, основание и срок (по пакету / длительность с даты / до конкретного дня).
2. **Заказчик и получатель** — поиск по фамилии, компании, БИН или создание нового (+). Получатель необязателен.
3. **Состав и стоимость** — доп. услуги к пакету и расчёт по прайсу на дату продажи: каждая строка, итог, предупреждение, если у услуги нет цены.
4. **Счёт** — сразу выставить счёт на всю сумму (Kaspi / Halyk / р/с / наличные) с номером счёта банка. Для бесплатного шага нет.

Всё сохраняется одной транзакцией: если что-то не прошло (например, нет цены), ничего не создаётся. Дальше — страница сертификата: отметить оплату → «Выпустить».

### Несколько сертификатов — группа сертификатов (с 25.10.2026)

Количество больше 1 — оформляется **группа №N** (тип «Платная» или «Бесплатная», решение 26.10.2026): одинаковые сертификаты (пакет, доп. услуги, срок, заказчик), у каждого свой номер и получатель. После мастера открывается страница группы.

- **Платная:** один счёт на всю группу (внутри — по строке на сертификат с общим номером счёта) → «Оплачен» на странице группы отмечает весь счёт (р/с — только Финансы) → «Выпустить» (появляется, когда оплачен каждый сертификат) → «PDF всех».
- **Бесплатная:** цель, основание, срок → директор «Согласовать» → «Выпустить» → «PDF всех».
- До выпуска счёт, оплата, состав, выпуск и аннулирование — только всей группой (на странице сертификата их нет, есть кнопка «Группа №N: счёт, оплата, выпуск» или «Группа №N: согласование, выпуск»). Получатель — в каждом сертификате отдельно.
- После выпуска сертификаты живут отдельно: бронь, погашение, возврат — поштучно; возврат одного не затрагивает остальные.
- Финансы: в реестре оплат у строки — «Группа №N (из N)»; «Сверено» по любой строке сверяет весь счёт группы.
- Отдельного пункта меню у групп нет: список «Группы сертификатов» (столбец «Тип»: Платная / Бесплатная) открывается с главной; группа — со страницы сертификата и из колонки «Группа» реестра. В реестре сертификатов — «Группировать по → Группа»: сертификаты собираются под заголовком «Группа №N · пакет × N», одиночные — в «Без группы». Продавец видит только свои группы.

### Одиночный сертификат: счёт и оплата в шапке (с 26.10.2026)

В шапке черновика продажи — «Выставить счёт» (по умолчанию весь остаток) → «Оплачен» → «Выпустить» (кнопка появляется только после полной оплаты). Частичные счета, сверка и исправления — во вкладке «Оплата».

### Снимок цен

Цена, себестоимость, поставщик и признаки исполнения каждой услуги фиксируются в строке сертификата на дату продажи (фазы 1, 3). Изменения прайса и пакетов на выданные сертификаты не влияют. Стоимость сертификата = сумма услуг пакета и доп. услуг по прайсу (решение 22.10.2026).

## Документ сертификата (PDF)

Кнопка **PDF** на странице выпущенного сертификата (статусы «Активен», «Забронирован», «Используется»). В документе:

- название и контакты отеля (`GIFTER_HOTEL_NAME`, `GIFTER_HOTEL_CONTACTS` в `.env`);
- номер, получатель (если не указан — «Предъявитель сертификата»), пакет, срок действия;
- состав: услуги и количество, **без цен**;
- условия (`config/gifter.php` → `certificate.terms`): погашение целиком, без обмена на деньги и т. д.;
- QR-код на страницу проверки.

Каждое скачивание пишется в историю сертификата («Скачан PDF сертификата»).

## Проверка по QR

QR ведёт на `/v/<код>` — публичную страницу без входа. Код — случайные 32 символа, создаётся при выпуске; номер сертификата для проверки не используется (его легко угадать).

Страница показывает **только** номер, статус («Действителен», «Используется», «Использован», «Срок действия истёк», «Аннулирован»), дату окончания и пакет. Имён, контактов и сумм нет. Ограничение — 30 проверок в минуту с одного адреса; страница закрыта от поисковиков.

Для рабочего сервера в `.env` должен быть указан настоящий `APP_URL` — из него строится ссылка в QR.

## Платные доп. услуги в бесплатном сертификате (19.10.2026)

Решение владельца: в мастере «Оформление сертификата» сумма показывает реальную сумму **к оплате**, а у доп. услуги бесплатного сертификата есть тумблер «Платная — оплачивает заказчик» (по умолчанию выключен — бесплатно).

- **Что бесплатно, что платно.** Услуги бесплатного пакета всегда бесплатны. Доп. услуга — по тумблеру. В платном сертификате оплачивается всё.
- **К оплате** = сумма платных услуг (сводка, карточка, группа). Бесплатная часть показывается отдельно: «Бесплатно по прайсу». Маркетинговый расход — себестоимость только бесплатной части.
- **Счёт** выставляется на платную часть (у группы — один счёт на всю платную часть всех сертификатов): сразу в мастере или позже в шапке карточки / группы.
- **Выпуск** — после согласования директором **и** полной оплаты платной части, в любом порядке. Полностью бесплатный сертификат работает как раньше.
- **Заказчик обязателен**, если есть платные услуги.
- **Тумблер** можно менять в черновике до согласования и до выставления счёта: в карточке, вкладка «Состав» → «Сделать платной / бесплатной» (с записью в историю).
- В показателях главной «Продажи за месяц» платная часть бесплатных сертификатов пока не учитывается (только сертификаты-продажи); маркетинговый расход считается по бесплатной части.
