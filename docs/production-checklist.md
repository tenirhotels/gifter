# Чек-лист запуска Gifter (по аудиту 19.10.2026)

Сделано в коде: выпуск после подтверждения оплаты Финансами (`GIFTER_REQUIRE_PAYMENT_RECONCILED`, по умолчанию включено); один номер брони — одна привязка за раз (блокировка); часовой пояс по умолчанию `Asia/Almaty`; продавец, назначенный менеджером, видит свой сертификат; бейдж «Комиссии» — быстрый запрос.

## Проверить на хостинге (владелец / администратор)
- `.env`: `APP_ENV=production`, `APP_DEBUG=false`, `APP_TIMEZONE=Asia/Almaty`, `APP_LOCALE=ru`, `APP_FALLBACK_LOCALE=ru`, `LOG_LEVEL=warning`, `SESSION_LIFETIME=60`, `SESSION_ENCRYPT=true`, `SESSION_SECURE_COOKIE=true`; не задан `GIFTER_REQUIRE_PAYMENT_RECONCILED=false`.
- Ключи: `APP_KEY`, `CONTACT_HASH_KEY`, `BACKUP_ARCHIVE_PASSWORD` — в менеджере паролей отдельно от сервера; `BACKUP_MAIL_TO` задан.
- Два администратора, у всех пользователей настроен 2FA.
- Cloudflare: Full (strict); адрес сервера хостинга закрыть для обращений, кроме Cloudflare (фаервол Hoster.kz / Plesk), иначе заголовок `X-Forwarded-For` можно подделать.
- Раз в квартал — проверка восстановления бэкапа в тестовую базу (`docs/security.md`).
- Перед обновлением: `backup:run --only-db`; после: `migrate --force`, `optimize`, `gifter:security-check`.

## Решения владельца (19.10.2026) — реализовано
- **Дата продажи и продавец** (менеджер): только с причиной (≥ 5 знаков); запись в журнал аудита, плитка директора «Ручные изменения продаж» и фильтр в списке сертификатов.
- **Контакты клиентов**: не более 30 разных клиентов в день на сотрудника (`GIFTER_REVEAL_DAILY_LIMIT`, администратор не ограничен); превышение — в журнал и плитка администратора «Лимит контактов».
- **Цены**: версию цены, добавленную директором, подтверждает администратор (`GIFTER_REQUIRE_PRICE_APPROVAL`); до подтверждения действует прежняя. Правила комиссий ведёт только администратор (уже так).
- **No-show**: на следующий день после планового выезда без заезда сертификат закрывается как использованный (бронь сверяется с PMS; отмена/расхождение — Финансам), комиссия начисляется.
- **Невыполненные услуги**: автоотметка «Использован» по выезду не срабатывает — сертификат остаётся сотруднику.

## Мониторинг и устойчивость (аудит, этап 2–3)
- **Ошибки сервера:** задайте `ERROR_MAIL_TO` — письмо о необработанной ошибке (класс, файл:строка, адрес без параметров; без данных клиентов; одинаковая ошибка не чаще раза в 15 минут). Нарушения бизнес-правил (`DomainRuleViolation`) — сообщением пользователю, без письма.
- **Планировщик:** `gifter:heartbeat` пишет метку каждую минуту; если её нет 10 минут, в «Безопасности» и на инфопанели администратора — ошибка. Проверьте задачу `php artisan schedule:run` в Plesk.
- **Cloudflare:** `TRUSTED_PROXIES=cloudflare` — доверять заголовкам только от Cloudflare и внутренних адресов сервера (без этого заголовок `X-Forwarded-For` можно подделать при прямом обращении к хостингу). Диапазоны — в `app/Support/TrustedProxies.php`, сверять с https://www.cloudflare.com/ips/. Если после включения ссылки или вход стали http — вернуть пустое значение и написать мне. Закрыть прямой доступ к серверу для всех, кроме Cloudflare, — в фаерволе Hoster.kz / Plesk.
- **Резервные копии:** ежемесячная копия на почту (1-го числа) и недельная; `gifter:backup-verify` по воскресеньям проверяет, что архив открывается паролем и в нём читаемый дамп (результат в «Безопасности»). Квартальное восстановление в тестовую базу остаётся обязательным.
- **CI:** `.github/workflows/ci.yml` — тесты на SQLite и MySQL 8, `pint`, `composer audit` при каждом push.
- **Адрес PMS** на рабочем сервере — только `https://`; переключение языка — POST с защитой CSRF.
